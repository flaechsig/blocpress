| Async-Rendering-Infrastruktur: PostgreSQL-basierte Job-Queue (Tabelle `render_job` im production-Schema) mit `SELECT ... FOR UPDATE SKIP LOCKED` für konkurrenzsicheres Job-Claiming ohne Message Broker. `@Scheduled`-Worker (`RenderJobWorker`) pollt alle 2s und verarbeitet den nächsten PENDING-Job. Webhook-Callbacks via `Thread.ofVirtual()` (Fire-and-Forget). Kein Kafka/RabbitMQ erforderlich — PostgreSQL reicht für die aktuelle Last. Zweistufige Bereinigung: Ergebnis-Bytes nach `result-retention` (Default 24h) löschen, Datensatz nach `record-retention` (Default 7 Tage) komplett entfernen. Synchroner Druck via `POST /api/render/{name}` schreibt ebenfalls Einträge (Audit-Log, `result=null`).
| 2
| icon:check-circle[role=green] DONE
