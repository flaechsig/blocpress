Als **Betreiber und Client-Entwickler** möchte ich, dass die ausgelieferte API-Beschreibung
von render vollständig ist und mit dem Code übereinstimmt, damit ich mich auf sie verlassen
und Clients daraus erzeugen kann.

**Warum.** Entscheidung [ADR-0013](../../09-decisions/ADR-0013.md): API-first aus `openapi.yml`,
umgesetzt mit Release 3.0 zusammen mit der Pflicht-Authentifizierung
([ADR-0017](../../09-decisions/ADR-0017.md)), damit die API nur einmal bricht.

Auf `/api/render/template/json` ziehen um: die Workbench (Vorschau, Regression),
`docker/README.md`, die Website, die E2E- und Lasttests und externe Clients, die JSON schicken.
Ob die Endpunkte dabei neue Namen bekommen (offene Frage aus
[ADR-0016](../../09-decisions/ADR-0016.md)), wird beim Bau in `openapi.yml` entschieden; dann
werden REQ-0107 und REQ-0108 abgelöst.
