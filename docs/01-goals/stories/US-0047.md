Als **Maintainer** möchte ich, dass ein Release ganz oder gar nicht veröffentlicht wird und alle Kanäle stimmen.

**Warum.** Nach dem Deploy auf Maven Central gibt es kein Gate mehr: Scheitert danach Docker Hub oder der Push, ist core veröffentlicht, ohne dass Tag und Images existieren. Der Push des Release-Workflows löst die Website nicht aus (nach 2.6.0 und 2.7.0 geprüft). Der Docker-Hub-Text (`docker/README.md`) beschreibt das render-Image, wird aber beim Quickstart-Image veröffentlicht.

Gefunden bei der Übernahme der Altdoku (2026-10-05), beschrieben in [07-deployment](../../07-deployment.md). Noch nicht
geplant.

**Entschieden (2026-10-06).**
- `pages.yml` startet zusätzlich per `workflow_run` nach einem erfolgreichen `release.yml`.
- Ganz oder gar nicht geht über mehrere Kanäle nicht. Der einzige nicht rücknehmbare Schritt,
  Maven Central, läuft daher als letzte Veröffentlichung: Images, dann Tag, dann Central auf
  dem getaggten Commit, danach Merge, nächste SNAPSHOT und GitHub Release.
- Das Quickstart-Image bekommt einen eigenen Docker-Hub-Text (`docker/README.quickstart.md`);
  `docker/README.md` wird beim render-Image veröffentlicht.

**Abnahme.** Beim nächsten Release wird die Website ohne weiteren Push neu veröffentlicht, die
Docker-Hub-Seiten von Quickstart und render zeigen ihren eigenen Text, und Maven Central kommt
im Lauf erst nach Tag und Images.

> **Nachweis (2026-10-07):** Release 2.7.1 (Actions-Lauf 37537618411): Images und
> Docker-Hub-Texte, dann Tag, dann Maven Central, dann SNAPSHOT und GitHub Release.
> `pages.yml` lief danach per `workflow_run` und veröffentlichte die Website. Docker Hub zeigt
> für Quickstart und render je den eigenen Text; blocpress-core 2.7.1 ist auf Maven Central.
