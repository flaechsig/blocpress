= ADR-004: PDF/RTF-Konvertierung bleibt in blocpress-core
:adr-status: accepted

== Status
Akzeptiert (2026-10-03) — `LibreOfficeProcessor` bleibt in `blocpress-core`; die Konvertierung
wird nicht in den Render-Service verschoben. Löst den Widerspruch um REQ-0004 auf.

== Kontext
REQ-0004 begründete, die Konvertierung gehöre „an den Rand (render-Modul)", damit der Kern
ohne LibreOffice bleibe. Tatsächlich liegt `LibreOfficeProcessor` in `blocpress-core`
(keine Compile-Abhängigkeit, `soffice` wird zur Laufzeit als Prozess gestartet); der
Render-Service nutzt ihn über `LibreOfficePool`. `blocpress-core` ist auf Maven Central
veröffentlicht, die Klasse damit öffentliche API. Zusätzlich soll der Weg offen bleiben,
Word-Vorlagen (DOCX) als weiteres Quellformat aufzunehmen (US-0036).

== Entscheidung
Die Konvertierung bleibt in `blocpress-core`. REQ-0004 wird durch REQ-0012 mit zutreffender
Begründung abgelöst. Ein Verschieben nach render findet nicht statt — weder als Deprecation in
2.7 noch als Entfernen in 3.0.

Nicht gewählt:

* *Nach render verschieben* (in 2.7 kopieren und die core-Klasse als `@Deprecated` markieren,
  in 3.0 entfernen) — der core-Build wäre ohne LibreOffice testbar geworden, aber die Bibliothek
  könnte keine fertigen PDF/RTF mehr liefern, und für Nutzer von `blocpress-core` wäre es
  langfristig ein Breaking Change.

== Begründung
Die Bibliothek soll aus einer Vorlage ein fertiges Dokument liefern, ohne dass man den
Render-Service betreibt. Ein weiteres Quellformat (Word) würde als zweite Umsetzung von
`TemplateDocument` in core entstehen und braucht dieselbe Konvertierung — sie gehört deshalb
neben die Merge-Pipeline, nicht in einen der Konsumenten. LibreOffice bleibt eine reine
Laufzeitvoraussetzung; Unit-Tests ohne LibreOffice laufen weiter (`TransformTest` wird ohne
`soffice` übersprungen).

== Konsequenzen
* link:../../spec/requirements/REQ-0004.md[REQ-0004] → `superseded` durch
  link:../../spec/requirements/REQ-0012.md[REQ-0012]; Tests sind auf REQ-0012 getaggt.
* Kein Breaking Change für Nutzer von `blocpress-core`.
* Für Word als Quelle (link:../../spec/stories/US-0036.md[US-0036]) muss die Konvertierung später
  das Eingabeformat als Parameter annehmen — heute nimmt `LibreOfficeProcessor` fest ODT an
  (temporäre Datei `.odt`). Das ist eine nicht brechende Erweiterung (zusätzliche Überladung).
* Der core-Build bleibt für den REQ-0012-Nachweis auf LibreOffice angewiesen (sonst
  `-Dreq.check.skip=true`).
