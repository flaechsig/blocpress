= ADR-002: Optionale JWT-Absicherung der Render-API
:adr-status: accepted

== Status
Akzeptiert (2026-10-02) — JWT wird per Laufzeit-Schalter `BLOCPRESS_AUTH_ENABLED`
aktiviert, Default **aus**. Gewählt aus drei Optionen (siehe Entscheidung).

== Kontext
Die Render-API ist laut Altbestand die einzige öffentlich exponierte Schnittstelle
von blocpress. Der Ist-Zustand vor dieser Entscheidung:

* `quarkus-smallrye-jwt` ist eingebunden, die Konfiguration `mp.jwt.*` aber
  auskommentiert („DISABLED FOR DEV").
* Alle Endpunkte von `RenderResource` tragen `@PermitAll`; Jobs und Dashboard sind
  per `quarkus.http.auth.permission.async` ausdrücklich freigegeben. Die API ist
  damit vollständig offen.
* Der Altbestand führt TI-4 („JWT-Authentifizierung, konfigurierbar via ENV") als
  DONE, `docs/dockerhub.md` nennt JWT für `/api/render/{name}` — beides trifft
  nicht zu (Widerspruch in der ROADMAP, link:../../spec/stories/US-0007.md[US-0007]).
* Bestehende Integrationen (u.a. tarifnova) rufen die API ohne Token auf.

Eine Entscheidung ist fällig, weil Doku und Code auseinanderlaufen und Betreiber
ohne vorgeschaltetes Gateway heute keine Möglichkeit zur Absicherung haben.

== Entscheidung
JWT-Authentifizierung wird **optional** und zur **Laufzeit** schaltbar:

* `blocpress.auth.enabled=${BLOCPRESS_AUTH_ENABLED:false}`. Umgesetzt über eine
  Quarkus-HTTP-Berechtigung (`quarkus.http.auth.permission.render-api`, Policy
  `authenticated`), deren `enabled`-Flag Laufzeit-Konfiguration ist — kein Neubau
  des (Native-)Images nötig.
* Eingeschaltet verlangen **alle Render-Endpunkte** ein gültiges Bearer-Token:
  `/api/render/template`, `/api/render/{name}`, `/api/render/jobs…` und das
  Dashboard `/api/render/dashboard…`.
* **Offen bleiben** der interne Import `/api/render/templates/import…`
  (Workbench → render, Netzwerk-Isolation wie 2026-03-01 entschieden) sowie
  Health/OpenAPI (`/q/…`).
* Nur **Authentifizierung** (gültige Signatur, ggf. Issuer, Ablauf) — keine
  Rollenprüfung; RBAC ist link:../../spec/stories/US-0021.md[US-0021].
* Schlüssel über die MicroProfile-JWT-Standardvariablen `MP_JWT_VERIFY_PUBLICKEY`
  bzw. `MP_JWT_VERIFY_PUBLICKEY_LOCATION` und `MP_JWT_VERIFY_ISSUER`. Ist JWT
  eingeschaltet, aber kein Schlüssel konfiguriert, **bricht der Start ab**.
* Der Dev-Schlüssel verschwindet aus der Produktionskonfiguration; er bleibt nur
  für Tests.

Nicht gewählt:

* *JWT verpflichtend* — bricht bestehende Integrationen ohne Token (tarifnova);
  höchstens Thema eines Major-Releases.
* *Bewusst offen, Absicherung nur über Netzwerk/Gateway* — nimmt Betreibern ohne
  Gateway jede Absicherung, obwohl die Abhängigkeit bereits vorhanden ist.

== Begründung
Der Default „aus" erhält das heutige Verhalten — ein Patch- oder Minor-Release
bricht niemanden. Der Laufzeit-Schalter erlaubt Betreibern, die API ohne eigenes
Gateway abzusichern, mit denselben Images. Ein Startabbruch ohne Schlüssel
verhindert den gefährlichsten Fehlbetrieb: „JWT eingeschaltet geglaubt, aber nichts
wird geprüft" bzw. jede Anfrage scheitert erst zur Laufzeit. Pfadbasierte
Berechtigungen statt Annotationen halten die Entscheidung an *einer* Stelle der
Konfiguration und lassen die generierten OpenAPI-Schnittstellen unberührt.

== Konsequenzen
* link:../../spec/stories/US-0007.md[US-0007] wird auf „optional" zugeschnitten und
  über link:../../spec/requirements/REQ-0008.md[REQ-0008] (401 ohne Token bei
  eingeschaltetem JWT, offen bei ausgeschaltetem) und
  link:../../spec/requirements/REQ-0009.md[REQ-0009] (Startabbruch ohne Schlüssel)
  belegt. Der ROADMAP-Widerspruch zu TI-4 ist damit aufgelöst.
* Restrisiko: Der Import-Endpunkt bleibt unauthentifiziert — render darf nur in
  einem Netz laufen, in dem allein die Workbench ihn erreicht.
* Wer JWT einschaltet, muss Dashboard-Aufrufe mit Token versehen (heute keine
  internen Aufrufer).
* `@PermitAll` an `RenderResource` entfällt; die Freigabe regelt allein die
  Konfiguration.
* render bekommt den ersten `@QuarkusTest` (Datenbank per DevServices/Docker).
* `docs/dockerhub.md` wird korrigiert (Auth-Spalte, `BLOCPRESS_AUTH_ENABLED`).
